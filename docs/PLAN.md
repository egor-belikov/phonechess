## Этап 0 — срочно, до следующего деплоя (½–1 день) — ✅ сделано, кроме закрытия порта (см. 0.4)

### 0.1 Убрать вход под чужим id (S2)
- Целевое поведение: `debug_uid` принимается только при `DEBUG=1` **и** `ALLOW_DEBUG_UID=1` **и** пустом `TELEGRAM_BOT_TOKEN`. На проде (токен задан) ветка недоступна в принципе.
- Для браузерных тестов — отдельный стенд/контейнер со своей БД, а не прод с `DEBUG=1`.
- Приёмка: на проде `{"type":"auth","init_data":"","debug_uid":123}` → close `4003`.

### 0.2 Премув и время хода (S1) — сделано иначе, чем планировалось: часы и так списывал `materialize_live_clocks`; исправлен `move_time_ms ≈ 0`, возврат за премув ограничен 300 мс
- Целевое поведение: флаг `premove` от клиента **игнорируется** для расчёта часов. Сервер списывает `elapsed = now - last_clock_at` минус компенсация лага `min(elapsed, LAG_COMP_MS)` (например, 300 мс, по аналогии с lichess). Ход, пришедший в пределах `LAG_COMP_MS` после хода соперника, фактически стоит 0 мс — премувы остаются «бесплатными».
- В `AGENTS.md` инвариант `is_premove=True → elapsed_ms = 0` заменить на новое правило.
- Приёмка: ход с `premove:true` через 20 с после хода соперника списывает ~19.7 с; настоящий премув (≤ 300 мс) — `0:00` в списке ходов.

### 0.3 XSS в истории профиля (S5)
- Целевое поведение: все пользовательские строки (`opponent`, `username`, `login_name`, `format`) выводятся через `textContent` или общую `escapeHtml()`.
- Приёмка: пользователь с `first_name = <img src=x onerror=alert(1)>` отображается текстом.

### 0.4 Webhook secret (S4) и закрытый порт (S8)
- `setWebhook(..., secret_token=TELEGRAM_WEBHOOK_SECRET)`; эндпоинт сверяет `X-Telegram-Bot-Api-Secret-Token`, иначе `403`.
- ✅ Сделано: `APP_BIND_ADDR=172.19.0.1` в `.env` на сервере, порт 8000 больше не публикуется наружу. Было: nginx на сервере ходит на `172.19.0.1:8000` (шлюз Docker), поэтому `127.0.0.1:8000:8000` сломает прокси. Нужно на сервере: `ufw deny 8000` / привязка к IP шлюза / общая docker-сеть с nginx.
- `docker-compose.yml`: `ports: "127.0.0.1:8000:8000"` (или сеть nginx без публикации порта); `ALLOWED_ORIGINS` — домен Mini App; пароль Postgres из `.env` без дефолта.

## Этап 1 — честные часы и устойчивость партий (2–3 дня) — ✅ сделано

### 1.1 Серверный флаг (G1)
- Целевое поведение: при каждом ходе/старте партии сервер планирует `asyncio`-задачу на момент `last_clock_at + remaining_ms` стороны, чей ход. Срабатывание → `materialize_live_clocks` → `game_update` с `timeout` обоим + итоги/рейтинг/уведомление. Ход отменяет и перепланирует задачу.
- (не делалось — серверного таймера достаточно) Клиент дополнительно может слать `{"type":"claim_flag","game_id"}` при нуле на часах соперника — сервер проверяет и завершает (страховка).
- Приёмка: игрок с 0:00 не ходит и не закрывает приложение → через ≤ 1 с партия завершена `timeout`.

### 1.2 Флаг при недостаточном материале (G2)
- Целевое поведение: при `timeout` проверить `board.has_insufficient_material(winner_color)`; если у победителя нет матующего материала → `1/2-1/2`, `result_reason = "timeout_vs_insufficient"`.
- Приёмка: у белых упал флаг, у чёрных голый король → ничья.

### 1.3 Возврат в партию (G3, G4)
- Целевое поведение:
  - после успешного `auth` сервер, если есть активная партия, шлёт `{"type":"active_game", ...matched-поля, color}`; клиент входит в партию и делает `subscribe_game`;
  - новое соединение того же `user_id` **вытесняет** старое (старому — close `4000`), а не отклоняется `4009`. Вкладка-призрак после обрыва сети больше не блокирует вход;
  - сделано так: старому соединению — `4010`, оно переподключается само, когда его окно снова становится активным (без кнопки).
- Приёмка: в партии закрыть Mini App и открыть снова за 5 с → та же партия, часы корректны, у соперника `reconnected`. Выключить Wi-Fi → включить → переподключение без `4009`.

### 1.4 Одна активность на пользователя (G5)
- Целевое поведение: `join_queue`, `start_bot_game`, `create_private_invite`, `join_tournament_waiting` отклоняются (`{"type":"error","code":"already_in_game"}`), если у пользователя есть партия с `result is None`. При матче пользователь удаляется из всех очередей.

### 1.5 Мелкие исправления жизненного цикла (G6, G7, G9, G10)
- `rematch_request`: только при `g.result is not None`; после создания реванша запомнить `rematch_game_id` и игнорировать повторные голоса.
- `respond_draw` accept → `_notify_game_finished_once`.
- `resign_game` / `forfeit_disconnected_player`: не писать в БД при `is_bot_game`.
- Причину `disconnect_turn_timeout` выставлять в `forfeit_disconnected_player` до `_persist_game_state`.
- ⏳ Не сделано: унифицировать сборку `game_update` в одну функцию `_game_update_payload(update, g)` — сейчас 8 копий словаря, отсюда расхождения.

### 1.6 Проверка ошибок клиенту — ✅ сделано
- Целевое поведение: на отклонённый `make_move` сервер отвечает `{"type":"move_rejected","reason":...,"fen":...}`; клиент откатывает доску к серверному FEN (сейчас при рассинхроне клиент «застревает» до следующего `game_update`).

## Этап 2 — безопасность REST и анализа (1–2 дня) — ✅ сделано

### 2.1 Аутентифицированный REST (S3, S6)
- Целевое поведение: все `/api/*` (кроме `/health`, `/build-meta.json`) требуют заголовок `Authorization: tma <initData>`; пользователь берётся из проверенного `initData`, параметр `telegram_id` удаляется. `auth_date` старше 24 ч → `401`.
- WS `auth` тоже проверяет `auth_date` (порог — 24 ч, чтобы не ломать долгие сессии; проверяется только при подключении).

### 2.2 Анализ (S7, R4, R5)
- `/api/analyze` требует auth и отказывает (`403 game_in_progress`), если у пользователя есть активная небот-партия.
- Лимит по `user_id`, а не по IP. Если IP всё же нужен — запуск uvicorn с `--proxy-headers --forwarded-allow-ips=<IP nginx>`.
- Два движка: один для ходов бота (приоритет), второй для анализа; либо очередь с приоритетом бота.
- `_analysis_cache` — LRU на N (например, 5000) позиций.

### 2.3 Самовосстановление Stockfish (G12)
- При исключении `EngineTerminatedError`/`BrokenPipe` — `_engine = None` и одна повторная попытка; fallback — случайный легальный ход, а не `legal[0]`.

## Этап 3 — надёжность и эксплуатация (3–5 дней) — ◐ сделано частично

Сделано: Telegram-вызовы вне event loop; выселение завершённых партий из памяти; закрытие «осиротевших» партий при старте; Stockfish 19 из официального релиза; pytest + CI; ретраи `/health` в `deploy.sh`.
Не сделано: асинхронная запись в БД, graceful shutdown/восстановление партий после рестарта, Alembic, ruff, отказ от `git add -A` в `deploy.sh`.

### 3.1 Не блокировать event loop (R1)
- Запросы к Telegram — через `httpx.AsyncClient` (или `asyncio.to_thread`) с фоновой отправкой (`create_task`), ошибки только логируются.
- Запись ходов в БД — `asyncio.to_thread` или async-драйвер; порядок записей внутри партии сохраняется (очередь на партию).

### 3.2 Очистка памяти (R2)
- Завершённые партии удаляются из `_games` через N минут после окончания (история уже в БД; реванш — по `game_id` из БД). Вместе с ними чистятся `_rematch_votes`, `_result_notified_games`, `_private_match_bot_messages`.
- Индекс `user_id → active_game_id` вместо линейного поиска.

### 3.3 Переживание рестарта (R3)
- Минимум: при старте помечать незавершённые партии в БД `result="aborted_server_restart"` (без рейтинга), чтобы история не содержала «вечных» партий.
- Лучше: graceful shutdown — `deploy.sh` ждёт, пока нет активных партий (или до таймаута), с баннером «обновление через N минут» и запретом новых матчей.
- Цель на будущее: восстановление активных партий из БД (FEN + часы + `last_clock_at` в wall-clock).

### 3.4 Миграции и инфраструктура (R6, R7)
- Alembic вместо `_ensure_schema_updates`.
- `pytest` для `pairing.py` (часы, инкремент, премув, флаг, ничьи, Elo, реванш) + smoke-тест WS через `TestClient`; `ruff` на бэкенде.
- GitHub Actions: lint + тесты на PR.
- `deploy.sh`: без `git add -A`, деплой только из чистого дерева и только запушенного коммита; `/health` с ретраями вместо `sleep 2`.

## Этап 4 — турниры (перед тем как снимать `tournament-ui-hidden`) (G11)

- Для турнирных партий запускать тот же таймер отмены; отменённая партия = поражение не сделавшего ход (или техническая ничья), с вызовом турнирного хука.
- При полном отключении игрока — удалять его из листов ожидания турниров; перед стартом турнира пинговать участников.
- Swiss: бай при нечётном числе, запрет повторных пар (backtracking), реальный Бухгольц для тай-брейка; порог игроков — «не меньше N», а не «ровно N».
- Состояние турнира в БД, чтобы рестарт не убивал турнир.
